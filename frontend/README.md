# Career OS 前端

TypeScript + Vite vanilla，使用本地系统字体。页面只调用 `/api` Service，不直接读写数据库或任意文件，不将正文放进 localStorage。

```sh
npm ci
npm run typecheck
npm run build
```

生产运行由项目根目录 `.venv/bin/python scripts/run.py` 提供 `frontend/dist` 和同源 API，入口 http://127.0.0.1:8765。不要直接打开 index.html；Vite dev 模式不包含后端代理，本轮以构建后的本地服务验收。

## 用户路径

1. 我的资料：手动编辑、显式保存当前版本。未保存输入保留在当前页面会话，关页前有浏览器提醒。
2. 求职：普通表单添加/编辑 JD，公司、岗位、正文必填；排除/删除可恢复，活动列表与归档分开。
3. 分析：每轮独立指令，先预览当前资料包，再显式发送同一包版本和幂等键。结果保留来源、状态、资料包与实际 payload 审计入口。测试与真实/未配置模式持续明确显示。
4. 简历：按岗位独立工作稿，自动保存与离开前 flush；冲突保留输入、展示服务器差异，用户合并后保存。AI 只生成待确认提案，不修改个人正本。每轮基于当前事实重新生成，不默认发送已有手改稿。
5. 保存正式版本 → 生成 PDF → 下载或预览 → 记录已经发生的投递。使用正常时间控件与中文状态，不要求填写内部 ID。旧投递固定当时岗位/版本/PDF。
6. 全局记录反馈：一文本框、可选 PNG/JPEG，保存即关闭且保留当前任务。反馈页可追加、回看与导出 Markdown/JSON；不采集页面正文。导出附截图引用，不把附件二进制塞入 JSON。

## 验收与限制

主控已实际浏览器操作上述测试模式主链、双窗口资料冲突、多个岗位隔离、删除岗位后的历史保留、反馈截图和导出。PDF 已用 macOS 预览打开且经 Poppler 渲染；Codex 内置浏览器预览可能受宿主限制，请使用“下载 PDF”后在本机打开。真实 Provider 需本地服务端环境配置，不能用测试结果冒充真实能力。

状态与证据见 `docs/execution/STATUS.md`、`docs/execution/EVIDENCE.md`。当前无富文本简历、文件导入或完整聊天式逐段编辑；这些不是本次新增范围。
