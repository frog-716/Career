# Career OS 前端

TypeScript + Vite vanilla，使用本地系统字体。页面只调用 `/api` Service，不直接读写数据库或任意文件，不将正文放进 localStorage。

```sh
npm ci
npm run typecheck
npm run build
```

生产运行由项目根目录 `.venv/bin/python scripts/run.py` 提供 `frontend/dist` 和同源 API，入口 http://127.0.0.1:8765。不要直接打开 index.html；Vite dev 模式不包含后端代理，本轮以构建后的本地服务验收。

## 界面结构

`src/workspace.ts` 负责视图、模块分区和 UI 选择状态；`src/main.ts` 负责 API、revision 冲突、编辑缓冲与反馈弹窗；`src/style.css` 定义固定视口与面板滚动。侧栏收起只修改 DOM 布局，不重建表单。岗位和工作卡按 scope/id 过滤，历史记录跳转带回类型与记录 ID。窄详情区将记录列表改为选择器，正文保留独立滚动区。

账户区由同一 shell 渲染：姓名字元不收缩，15px 字号、4px 间隔，头像和姓名共用居中网格。方形头像周围的本地 SVG 流光使用纹理位移、遮罩及 CSS 动画；遮罩避开头像主体，装饰不参与点击或辅助阅读，减少动态效果偏好下停止动画。没有运行时外部素材请求。

本批新增 `src/knowledge-ui.ts`，负责 Wiki 选材/来源/候选/修订和公司组织、机会关联、简历用途界面。验收见 [Wiki 与业务对象整合](../docs/execution/WIKI-DOMAIN.md)。本批后续鼠标整改见下文。

## 用户路径

当前导航：今天、职业 Wiki、求职机会、简历工作台、任职、面试与复盘、足迹。岗位内保存下一行动和日期、追加研究/沟通/面试/Offer原话；工作卡保存任职阶段、具体事务、协作和收获。页面展示的是用户记录，尚不提供自动搜岗/研究、真实语音或阶段总结AI。资料在职业 Wiki 中按原始资料 → 待确认 → 当前条目沉淀；基础资料为同页独立分区。原版简历保持独立。接口和本轮浏览器证据见 [任务工作台批次](../docs/execution/TASK-WORKSPACE.md)。下列较早的分析/文字草稿链路保留，但不能理解为纸面编辑器的结构化AI已接通。

1. 职业 Wiki：原始文本保留原貌，手工整理候选、确认、修订/撤回；多来源同范围关联。当前事实按类别与个人/机会/任职筛选。基础资料：姓名/邮箱/电话/微信/GitHub/个人网页显式保存；旧混合文本先明确整理并归档，其余作为候选确认。未保存输入保留在当前页面会话，关页前有浏览器提醒。
2. 求职：普通表单添加/编辑 JD，公司、岗位、正文必填；排除/删除可恢复，活动列表与归档分开。
3. 分析：每轮重新选取非必选 Wiki、独立指令，先预览当前资料包，再显式发送同一包版本和幂等键。结果保留来源、状态、资料包与实际 payload 审计入口。测试与真实/未配置模式持续明确显示。
4. 简历：主入口打开独立 `/editor.html`，复用既有妙搭纸面编辑器。早期岗位文字草稿与投递记录保留在材料页“早期记录”分区，尚未转成结构化工作稿。
5. 保存正式版本 → 生成 PDF → 下载或预览 → 记录已经发生的投递。使用正常时间控件与中文状态，不要求填写内部 ID。旧投递固定当时岗位/版本/PDF。
6. 全局记录反馈：一文本框、可选 PNG/JPEG，保存即关闭且保留当前任务。反馈页可追加、回看与导出 Markdown/JSON；不采集页面正文。导出附截图引用，不把附件二进制塞入 JSON。

## 验收与限制

主控已实际浏览器操作上述测试模式主链、双窗口资料冲突、多个岗位隔离、删除岗位后的历史保留、反馈截图和导出。PDF 已用 macOS 预览打开且经 Poppler 渲染；Codex 内置浏览器预览可能受宿主限制，请使用“下载 PDF”后在本机打开。真实 Provider 需本地服务端环境配置，不能用测试结果冒充真实能力。

状态与证据见 `docs/execution/STATUS.md`、`docs/execution/EVIDENCE.md`。独立工作台支持原版富文本纸面编辑；文件导入、线上资料迁入、结构化 AI 逐段修订尚未接入。正式版本可以引用到方向或机会，实际投递已从机会的固定版本用途接通；用途与投递仍是两个动作。


## 既有简历工作台本地化

入口 `http://127.0.0.1:8765/editor.html`。源码来自 app_17dspw78s10 发布分支 main 的 `cc4f247a6556bb7369e5a24cbf2539e0fd3679a8`，实际入口 legacy-app.js / legacy.css；保留原纸面编辑、分区条目排序、富文本快捷键和撤销重做。字体及许可证随源码保留在 public/assets/fonts。没有复制线上简历样例、平台 SDK 或 .env。

纸面内容直接编辑；选中分区/条目显示原版操作按钮。草稿自动保存且可手动重试，冲突比较两份内容后人工选择。正式版本保存同时生成实际 PDF，历史可下载/恢复；恢复前当前稿进入独立恢复点。命名使用页面内对话框，兼容不支持 prompt 的内置浏览器。JSON/MD 可导出，JSON 导入尚未提供。

PDF 延用原版 html2canvas/jsPDF 图片式渲染，不具备可选中文字；不会将此路径称为可检索文本 PDF 验收通过。渲染时锁定编辑并冻结文档，失败可使用原请求重试。界面正文不存 localStorage；未保存时关页有提示。API与验收范围见 `docs/execution/RESUME-WORKBENCH.md`。

## 冷启动整改

机会 → 简历 → 关联已保存版本 → 记录投递，填写实际时间、渠道和状态。机会页回看新旧投递及冻结正文/JD/PDF；旧文字稿入口保留。渲染从 `resume_snapshot` 读取，不从当前工作稿拼接。`main.ts` 复用同一登记与状态界面，`knowledge-ui.ts` 只在机会用途提供投递动作；后端再验证用途匹配。

`editor/legacy.css` 统一修复四类章节新增工具的鼠标命中：常显、在标题后按flex正常排列；条目工具保留选中并支持hover/focus，小屏章节直接显示新增。回调、单click、焦点、撤销恢复与PDF实现未改。真实验收和已知限制见 [冷启动整改](../docs/execution/COLD-START-REPAIR.md)。


## 事实闭环页面

`profile-ui.ts` 管理基础字段表单、旧文本整理与CAS；`record-ui.ts` 为机会、工作卡及聚合记录复用更正/历史/选段候选操作。`legacy-app.js` 提供明确选材和来源提示，保存工作稿成功后再发选材CAS；不确定响应复用同一请求。撤销/重做保留服务端来源历史，恢复正式版本采用冻结来源。

机会编辑器URL携带job_id，返回机会简历tab；来源可深链当前Wiki条目或基础资料。普通面试/足迹空状态只指向创建所属的机会或工作卡。分析预览先展示可读正文，允许返回调整，完整JSON收在技术详情中。验收详见 [事实闭环](../docs/execution/FACT-LOOP.md)。



基础资料包括微信、GitHub和可增删的个人网页；表单输入只在当前DOM，切页不保留未提交内容，重新进入读取服务端已保存资料，后台CAS不展示为正常页面版本徽标。保存基础资料会同步当前简历的姓名和联系方式区；第一行显示身份联系方式，第二行显示GitHub及其他个人网页。简历GitHub从用户提供的PNG徽标中只显示猫图形，并与电话、邮箱、微信图标保持14px视觉尺寸；未填写微信时提供带微信图标的补填入口。
