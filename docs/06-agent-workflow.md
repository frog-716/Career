# Astra高规划 / Luna中执行

## 模型与权限

用户指定主控 `gpt-6-astra` + `high`，执行者 `gpt-5.6-luna` + `medium`。这是开发分工，不是产品运行时LLM配置，二者的账号/凭据不可混同。

2026-09-14打包宿主列出上述模型与档位；新宿主仍须检查实际可用性。提示词自称某模型不会切换运行模型。默认配置参考 `config-templates/codex-config.toml.example`；采用前核对宿主。模型不可用时报告缺项，主控仍可做不依赖该执行者的工作，不伪称Luna参与。

## 职责

| Astra | Luna |
| --- | --- |
| 分批、产品取舍、Interface、依赖与文件所有权 | 执行已明确验收的有限任务 |
| 处理跨模块变更、事实治理、并发与数据风险 | 页面、接口实现、测试、适配、机械整理 |
| 整合代码、实际浏览器验收、最终结论 | 返回变更、运行证据、疑问与风险 |
| 规格审查并裁决发现 | 可承担独立规范审查，不能自己宣布产品完成 |

主控先形成可执行批次，不无限规划。一个Luna任务最好覆盖一个可验证结果，而不是仅“改一个文件”。复杂任务拆成有限目标，每个有Interface和完成条件。

## 派工与上下文

使用 [Luna派工模板](../prompts/LUNA-TASK.md)。只传目标、相关契约/路径、允许修改文件、输入输出、验收和已知限制；不传完整旧聊天。每个可并行任务的修改文件互不重叠，公共schema/核心Interface由Astra先固定。

允许后台临时Subagent，不创建额外用户任务/可见分支/worktree。使用宿主已有subagent调用；如支持model/reasoning参数，明确传Luna/medium。需要模型覆盖的宿主若不允许全历史fork，使用最小上下文而不是全历史继承。

不将宿主API字段写成跨工具通用代码。未提供subagent工具时，Astra继续做可执行工作并报告调度缺项；不要擅自用用户可见的新任务模拟后台协作。

## 每批流程

1. Astra写小批次任务：用户结果、依赖、Interface、验收、Luna文件范围。
2. 影响数据/并发/主链的行为先写有意义失败测试，再实现；视觉小修改直接浏览器验收。
3. 并行仅用于独立工作。Luna报告返回后Astra读代码并实际验证，不只采信自报。
4. 两路审查：规格轴（是否满足契约与事实边界）；规范轴（深模块、维护、测试、风险）。优先用新上下文独立审查；不要求两个并行Astra长时间空转。
5. 解决阻塞发现，验收主路径，保存批次证据与STATUS，继续下一可执行批次。

## Gate与停止

普通UX/字段/工具链选择自主解决。只有真实资料不明且阻塞、不可恢复数据操作、主链无法接入、重大产品取舍或必须外部接入无法确认时暂停依赖部分，其他独立工作继续。

达到roadmap的首次全链路体验终点后停止扩展；用户反馈驱动下一轮。暂停点不是旧票号，不加载旧项目状态。中断后用 [恢复提示词](../prompts/RESUME.md) 从STATUS和实际代码继续。
