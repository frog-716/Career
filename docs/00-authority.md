# 权威顺序与现状

## 正本顺序

1. 新项目中用户最新明确指令。
2. 本包的用户需求：`01-product.md`、`02-context-contract.md`、`04-journeys.md`。
3. 工程起点与分批建议：`03-architecture.md`、`07-roadmap.md`。当前主 Agent 可自主做最小合理调整，更新所属文档并说明理由，不反复制造架构Gate。
4. 验收：`05-acceptance.md`。
5. `fixtures/`、官方来源：仅提供参考与验证，不覆盖产品需求。`archive/` 只作历史追溯，不进入当前权威链。

出现冲突时修改同一正本，不复制一份“最终最终版”。新增会话内容先按事实/提案/产品决策分类，再更新对应位置。存档和分析不成为新事实来源。

## 已确认的用户需求

- 纯本地项目，无云端部署、多端同步要求；AI可经配置使用远端或本地模型。
- 资料可人工编辑，也能由AI依照用户明确指令写入；AI自行推断的事实变更需确认。
- 每次分析只读取当前有效资料，严格隔离旧修订、对话残留与未确认分析。
- 求职全链路、语音模拟、转写复盘、谈薪Offer，以及任职事项、协作记录和阶段总结均属于产品目标。
- 任务驱动交互，AI承担理解整理，用户提供材料与决策；保留自由编辑。

## 当前事实

- 当前已有可运行的本地应用、结构化简历工作台、虚构案例、生产数据目录和备份链；实际交付范围只以 `execution/STATUS.md` 为准。
- 用户个人事实只来自运行时正本，不从旧对话、源码、历史证据或归档材料推断。
- 真实模型、语音、招聘来源及其他外部能力仍须分别按当前状态实测；演示、TestProvider 或历史报告不能代替。

## 工程默认与待核验项

当前实现采用单体后端、任务前端、单个 SQLite 数据库和本地附件目录；分析审计与业务正本以表和事务边界隔离。真正不可降级的是读取范围、来源和写入权限。

模型供应方、具体语音模型、招聘平台接口、线上简历历史可导出程度与本机性能尚待核验。缺少某个接入时完成独立部分并准确报告未验收点；不能用演示假装通过。
