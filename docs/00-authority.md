# 权威顺序与现状

## 正本顺序

1. 新项目中用户最新明确指令。
2. 本包的用户需求：`01-product.md`、`02-context-contract.md`、`04-journeys.md`。
3. 工程起点与分批建议：`03-architecture.md`、`07-roadmap.md`。Astra可自主做最小合理调整，更新所属文档并说明理由，不反复制造架构Gate。
4. 工作流与验收：`05-acceptance.md`、`06-agent-workflow.md`。
5. `reference_code/`、`fixtures/`、官方来源：仅提供参考与验证，不覆盖产品需求。

出现冲突时修改同一正本，不复制一份“最终最终版”。新增会话内容先按事实/提案/产品决策分类，再更新对应位置。存档和分析不成为新事实来源。

## 已确认的用户需求

- 纯本地项目，无云端部署、多端同步要求；AI可经配置使用远端或本地模型。
- 资料可人工编辑，也能由AI依照用户明确指令写入；AI自行推断的事实变更需确认。
- 每次分析只读取当前有效资料，严格隔离旧修订、对话残留与未确认分析。
- 求职全链路、语音模拟、转写复盘、谈薪Offer，以及任职事项、协作记录和阶段总结均属于产品目标。
- 任务驱动交互，AI承担理解整理，用户提供材料与决策；保留自由编辑。
- 新项目采用Astra高规划、Luna中执行；主控统一审查和验收。

## 新项目初始状态

- 没有业务应用、真实数据、已配置模型、已连通招聘账号或已迁出的妙搭档案。
- 有一份可独立测试的备份参考代码、虚构案例及完整开发契约。打包验证不等于业务验收。
- 用户个人背景、当前工作单位、最新目标岗位、技能熟练度均待新项目导入后确认。旧对话中的个人经历不随包携带。
- 历史系统验证过“本地持久化与任务引用”这条技术路线；它的演示分析不能证明真实LLM能力。

## 工程默认与待核验项

建议以单体后端、任务前端、SQLite和本地文件实现；两个SQLite文件隔离正本与分析的设计是工程起点，不是为了模型完美而禁止变更的定理。真正不可降级的是读取范围、来源和写入权限。

模型供应方、具体语音模型、招聘平台接口、线上简历历史可导出程度与本机性能尚待核验。缺少某个接入时完成独立部分并准确报告未验收点；不能用演示假装通过。
