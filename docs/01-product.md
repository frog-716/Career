# 产品目标与边界

本页是产品总览。跨模块长期对象与一级导航以[长期 Career 模型](target/long-term-career-model.md)为唯一正本；Opportunity流程以[Product Model](target/opportunity/opportunity-product-model.md)、[Domain Model](target/opportunity/opportunity-domain-model.md)、[UI Flow](target/opportunity/opportunity-ui-flow.md)、[Context & Ingestion](target/opportunity/context-ingestion.md)四份目标为准。本页只同步体验摘要，不另建字段正本。下述目标不代表已经实现，现状与限制见[STATUS](execution/STATUS.md)及[AS-IS](audit/AS-IS-system-map.md)。

## 核心心智模型

围绕当前职业任务帮助用户理解情况、准备行动、保存结果、积累可复用经验。求职与任职共用资料，但不同工作期和任务的材料按需隔离。价值来自少重复解释、建议有依据、经验可复用，不以功能数量或“全球首次”验收。

核心对象分工：Raw保留原始材料；Project、Employment、Opportunity、Person拥有自己的业务身份、状态和关系；Wiki保存有来源的当前语义；Cognition是Wiki里可跨经历复用的个人认知；Wiki Compiler逐条提出Wiki Patch供用户审批；ResumeDocument属于单个Opportunity，Submission冻结真实投递材料。一级导航固定为 **Wiki / 机会 / 项目 / 任职**。

## Opportunity本周期目标

**一次Opportunity = 一次具体求职尝试。** 公司、岗位、JD与可选外部链接构成创建入口，Company复用或新建。当前尝试由Opportunity作为唯一业务正本，不再以SearchCycle/JourneyPlan驱动一套并行状态。

- phase：写简历 / 已投递 / 面试 / Offer，表示最后推进到哪里。
- result：`active / accepted / rejected / withdrawn`，表示是否继续及如何结束。`result != active`进入“已结束”View，它不是第五个phase。任何阶段可被拒绝或主动退出；只有Offer阶段可accepted。
- 主路径：创建机会→投递准备→记录已投递→招聘沟通→确认真实面试→每轮准备/模拟/真实/复盘→Offer/谈薪→结束。允许先聊后投、直接约面、多机会并行，不以必填简历强制串行。

机会管线一行一个Opportunity，展示公司、岗位、阶段、阶段日期及可选链接图标，提供全部/四阶段/已结束View。点击整行进入Opportunity Workspace：稳定顶部、当前阶段工作区、岗位情报、投递材料、Timeline。

当前阶段工作区由phase决定主要动作；岗位情报合并展示CompanyResearch与OpportunityResearch，但后台保持各自所有者；投递材料只回答当时发了什么，永久冻结实际简历、Greeting和日期；Timeline从真实业务对象聚合，不记录普通保存、改字号、AI重跑或接受Patch。

AI贴着简历、沟通、研究、面试、Offer等具体任务出现，不设置万能AI入口；AI建议通过Patch确认，用户手动编辑正式资料直接保存。长期任职积累仍可用于下次求职，但Offer accepted不自动创建Employment。多Offer Comparison及自动招聘进入Later，见[Roadmap](07-roadmap.md)。

## 用户体验

2026-09-14 最新界面约束：参考 ChatGPT 的白灰极简工作区，左侧导航可完全收起，底部本地工作区菜单承载设置与反馈历史。应用占满一个浏览器视口，标题、模块切换及主动作固定，长列表和正文只在各自面板内滚动，不用整页长卷寻找操作。去掉口号、统计装饰、重复说明；限制只在相关动作处简短说明。2026-09-24 用户确认设置页采用顶部标签分区，按概览、AI 模型、搜索、数据与版本组织；具体内容按项目当前能力适配，不把示意图中的占位状态当作真实功能。

2026-09-15 账户区视觉修订：姓名及 emoji 保持清晰间距和垂直居中，整体右移为头像留空间，窄屏不得通过缩小挤紧姓名解决布局。头像基础边框为正方形；特效参考《斩神》动画的层次与流动感，用户已否定蓝紫霓虹双框、碎线和横穿头像的白色斜线方案。

Opportunity目标采用机会管线与阶段Workspace，按当前阶段突出主要动作，历史进入材料区与Timeline；旧平级tabs/计划阶段是现有实现，不再作为目标布局。任职采用工作卡列表与所选工作详情，事务、协作、收获各自记录和回看。完整纸面 Resume Editor 从当前机会进入；A4纸面保持固定比例并在宽桌面居中，较窄桌面通过编辑画布和工具区各自滚动保持内容与操作可达，不压缩或改造纸面模板。简历版本属于机会自己的文档，投递材料保持冻结。切换导航或收起侧栏不得丢失已保存内容；长正文按需阅读，不同时展开所有记录。

一级导航：Wiki、机会、项目、任职。姓名等基础资料从 Wiki → 基础资料管理，不再单列“个人资料”入口；调整入口不删除或改写已有资料。完整简历编辑器不设一级入口，从机会进入。反馈与设置独立可达。用户可在一级导航上右键置顶模块，置顶项移动到第一位并成为启动时首页；默认首页只负责进入用户选择的工作区，不另建一套任务状态。

首次进入可“添加机会”或整理 Wiki 基础资料，任务中再补缺项。资料从明确业务页面进入，文本入口长期可用；文件解析和AI提取按实际接入能力标明，未知不编造。岗位名称自由输入，来源时间系统记录。次要操作放详情或菜单；全局提供“记录反馈”快捷入口。

界面呈现任务、材料和建议，隐藏数据库ID、证据枚举、内部模型名称等用户不需要理解的字段。模拟必须关联目标真实轮次；本期由用户复制Context Pack到新ChatGPT对话进行语音模拟，再上传转写文本。简历保留手动编辑、讨论、版本和本地PDF。

## Resume Editor 在 Career 中的入口

简历编辑参考用户已有的[妙搭简历工作台](https://fcnxusey6bqe.feishuapp.com/app/app_17dspw78s10)，保留纸面直接编辑、结构化分区和条目、格式、撤销/重做、版本历史与PDF能力；不能以纯文本编辑框替代后宣称完成。它不再是独立一级模块，用户从当前机会进入完整编辑器。

每个Opportunity拥有自己的ResumeDocument；初次创建和版本行为、Profile同步及冻结边界按[长期 Career 模型](target/long-term-career-model.md)与Opportunity正本执行。自动保存更新当前稿，`⌘S`创建有名称的ResumeVersion；Submission冻结真实发送材料。

ResumeUse与“关联已保存版本”不是目标模型；旧记录先分清测试/真实资料，按实施计划处理，不用复杂兼容层保护测试数据。保留纸面编辑体验；参考系统的功能/模板数量不是新增范围，存储适配不构成重做编辑器的理由。

## AI责任

- 理解、提取、选材、匹配、生成草稿、追问、复盘、提出行动和资料修订。
- 显示关键结论来源与未知，不以编造经历填满字段。
- 用户决定重要方向与对外行动。系统记录真实发生的投递/发送，不把草拟等同发生。
- 资料正本和分析分离的全部规则以 [上下文契约](02-context-contract.md) 为准。

## 本地与外部能力

本地应用无需云端发布；PDF、转写和附件写本机。选用远端LLM会发送明确选择的材料，须在界面显示发送范围并提供配置。使用本地LLM可保持分析不出机器，但需测内存、速度与质量。

完全断网可以查看、编辑、导出已存资料并运行已安装模型；不能获得最新招聘或公司信息。电脑睡眠/关机时后台暂停，下次启动恢复。

能力目标与实现状态分别判断：Opportunity 人工主链及相应任务 AI 按四份正本分批实施；Project 独立入口、Employment / Person 生命周期已分别完成 Phase B、C。Phase D1 的手工 Raw 与 Wiki Semantic 已完成自动验证、Runtime 更新、两段用户 UI 验收和 Git 收口；Phase D2 已 READY，尚未开始。Compiler、Cognition 自动提炼和新 Wiki 的 AI Context 读取不在 D1。现有 participant/T14 能力继续作为旧兼容实现；具体代码、Runtime 与验收状态见 [STATUS](execution/STATUS.md)。真实模型质量单独验收；内置语音、Offer 比较等后续能力不列为当前交付。

不能保证：全网招聘无人值守覆盖、无授权账号读取、领导真实心理、公司未公开内部事实、AI零幻觉、精确录用概率、谈薪结果、从任意PDF无损恢复编辑结构。外部数据不足时输出待验证问题。

## 完整产品方案：从职业任务到长期积累

本方案为目标设计，不等于已实现；当前实现和验收只在 execution/STATUS.md。第一性原理：用户需要在信息不全时做更好的决定、完成具体行动，并保留能改变下次决策的证据。信息越多并不天然越好，功能越多也不天然先进。产品价值用「每次准备少重复解释、决策依据可追溯、下一步可执行、经历能再次利用」评估，不承诺前人未做过或成功率。

长期路线连接求职与任职积累，但不是一个必须点完的向导。Opportunity本期主链以上文及模块正本为准；模拟绑定真实轮次，多Offer比较留待后续。任职由用户独立管理，被拒后可复盘或创建新的求职尝试。

### 降低杂乱经历对分析的影响

不要求用户先整理完人生。入口接受原话，先确定「当前要做的决定」；缺少会改变建议的信息时才追问。Opportunity材料从明确业务入口进入Raw，经对应Skill提出按目标分组的Patch；项目按问题、本人职责、动作、结果、证据组织，区分本人和团队贡献。

每轮先保留职业目标与硬约束，再选择与问题有关的经历及反证，最后按需展开原文。页面提供入选材料及遗漏补充入口；未选中的经历仍保存在本地。技术上以版本依赖和任务范围约束材料，不能只依赖一句“忘记以前的内容”。协议与验收见 02-context-contract.md。

### 领导同事建模的合理形态

采用可更新的协作档案：角色/决策权、共同目标、当前承诺、可观察沟通偏好、关键事件、待验证假设、下一验证动作。一次“迟迟不回复”至少考虑优先级、任务不明确、职责边界、资源限制等解释；根据后续响应更新解释，而非把“对方针对我”固化为事实。建议应回答下一次如何澄清交付和期待、如何给出选项、如何留下结果证据。离开该工作期后，不自动把私人聊天和他人档案送入求职分析。

### 首试范围及反馈迭代

首试MVP是历史基线，不限制当前周期。Phase A 与 Phase B 已完成；Phase C–I 仍是后续目标，不代表已实现。Opportunity细节仍按其四份正本分批落地；手动闭环与真实AI分别验收。

每轮改进从实际反馈选出最影响完成任务的问题：主控读原话和可复现路径 → 在反馈外形成改动提案 → 修改所属产品文档 → 一个可验收批次 → 用隔离资料验证 → 回到真实试用。反馈不自动变产品结论，也不由应用擅自修改代码。观察任务完成阻碍、重复输入、资料纠错、建议采用/拒绝理由；不悄悄采集正文或遥测。

## 历史产品摘要：职业事实 Wiki（2026-09-14）

本节早于新的[长期 Career 模型](target/long-term-career-model.md)，只保留仍兼容的Wiki使用背景。与新模型不一致的旧入口、ResumeUse、Project/Employment范围描述已由新正本取代。

个人职业事实仍由Wiki/profile承载，Opportunity与Employment保留各自业务归属。Opportunity目标中Raw是依据，Patch是待确认提案，Wiki与Research/Interview等各自拥有当前认知；不将所有业务数据复制到Wiki。ContextCompiler按任务声明读取当前获准资料。

基础资料从 Wiki → 基础资料进入，不再设置独立个人资料入口；仅调整入口，不删除或更改资料。页面数量不是对象数量；主要按钮必须带当前对象与用途，不用“记录一下”把所有事件混成一种材料。当前一级导航以长期 Career 模型为准。

## 历史决定摘要：冷启动整改后的事实生命周期（2026-09-15）

本节保留仍有效的 Profile、来源追溯、PDF/投递冻结和并发保护决定。与新长期 Career 模型或 Opportunity 正本冲突的旧对象/入口描述已由新正本取代；本节不证明这些目标能力已实现。

基础资料只拥有姓名、邮箱、电话、微信、GitHub及个人网页；长期经历、能力、职业目标及地点/出差等限制属于个人 Wiki。TargetRole / SearchCycle 是旧实现与旧计划中的可选引用，不是新的必需对象或求职状态正本；具体招聘条件属于 Opportunity 的 JD。

用户可以把已确认的 Wiki 知识用于所属机会的简历表达，并保留明确选择的 source_refs（如 ID、revision/hash）；表达修改不能倒写职业事实。不得因编辑、跨简历复制或普通版本保存建立隐含的复制 lineage。正式版本、PDF 和历史投递保持冻结；编辑器返回所属 Opportunity。

既有研究/面试 note 与任职工作记录中的原话/更正历史是旧实现和迁移现状，不据此为新模型增加重复实体。Opportunity 新 Raw 的更正规则按 Opportunity 正本与 Context 合同执行；真实或未知旧记录不因新目标被猜测删除。面试允许未投递先确认，模拟必须绑定同机会真实轮次；求职 Timeline 按领域对象投影。
