# 产品目标与边界

本页是产品总览。Opportunity本周期以[Product Model](target/opportunity/opportunity-product-model.md)、[Domain Model](target/opportunity/opportunity-domain-model.md)、[UI Flow](target/opportunity/opportunity-ui-flow.md)、[Context & Ingestion](target/opportunity/context-ingestion.md)四份人工确认目标为准；本页仅同步体验摘要，不另建字段正本。下述目标不代表已经实现，现状与限制见[STATUS](execution/STATUS.md)及[AS-IS](audit/AS-IS-system-map.md)。Employment/Project/People/Growth维持现有边界，本周期不提前重构。

## 核心心智模型

围绕当前职业任务帮助用户理解情况、准备行动、保存结果、积累可复用经验。求职与任职共用资料，但不同工作期和任务的材料按需隔离。价值来自少重复解释、建议有依据、经验可复用，不以功能数量或“全球首次”验收。

## Opportunity本周期目标

**一次Opportunity = 一次具体求职尝试。** 公司、岗位、JD与可选外部链接构成创建入口，Company复用或新建。当前尝试由Opportunity作为唯一业务正本，不再以SearchCycle/JourneyPlan驱动一套并行状态。

- phase：写简历 / 已投递 / 面试 / Offer，表示最后推进到哪里。
- result：`active / accepted / rejected / withdrawn`，表示是否继续及如何结束。`result != active`进入“已结束”View，它不是第五个phase。任何阶段可被拒绝或主动退出；只有Offer阶段可accepted。
- 主路径：创建机会→投递准备→记录已投递→招聘沟通→确认真实面试→每轮准备/模拟/真实/复盘→Offer/谈薪→结束。允许先聊后投、直接约面、多机会并行，不以必填简历强制串行。

机会管线一行一个Opportunity，展示公司、岗位、阶段、阶段日期及可选链接图标，提供全部/四阶段/已结束View。点击整行进入Opportunity Workspace：稳定顶部、当前阶段工作区、岗位情报、投递材料、Timeline。

当前阶段工作区由phase决定主要动作；岗位情报合并展示CompanyResearch与OpportunityResearch，但后台保持各自所有者；投递材料只回答当时发了什么，永久冻结实际简历、Greeting和日期；Timeline从真实业务对象聚合，不记录普通保存、改字号、AI重跑或接受Patch。

AI贴着简历、沟通、研究、面试、Offer等具体任务出现，不设置万能AI入口；AI建议通过Patch确认，用户手动编辑正式资料直接保存。长期任职积累仍可用于下次求职，但Offer accepted不自动创建Employment。多Offer Comparison及自动招聘进入Later，见[Roadmap](07-roadmap.md)。

## 用户体验

2026-09-14 最新界面约束：参考 ChatGPT 的白灰极简工作区，左侧导航可完全收起，底部本地工作区菜单承载设置与反馈历史。应用占满一个浏览器视口，标题、模块切换及主动作固定，长列表和正文只在各自面板内滚动，不用整页长卷寻找操作。去掉口号、统计装饰、重复说明；限制只在相关动作处简短说明。

2026-09-15 账户区视觉修订：姓名及 emoji 保持清晰间距和垂直居中，整体右移为头像留空间，窄屏不得通过缩小挤紧姓名解决布局。头像基础边框为正方形；特效参考《斩神》动画的层次与流动感，用户已否定蓝紫霓虹双框、碎线和横穿头像的白色斜线方案。

Opportunity目标采用机会管线与阶段Workspace，按当前阶段突出主要动作，历史进入材料区与Timeline；旧平级tabs/计划阶段是现有实现，不再作为目标布局。任职采用工作卡列表与所选工作详情，事务、协作、收获各自记录和回看。资料、简历工作稿、正式版本及早期文字记录分开；独立简历工作台在当前窗口打开，正式版本可明确关联方向或机会，但关联不等于投递。切换导航或收起侧栏不得丢失已保存内容；长正文按需阅读，不同时展开所有记录。

一级导航：今天、职业 Wiki、求职机会、简历工作台、任职、面试与复盘、足迹。基础资料在职业 Wiki 中管理；公司与方向位于本地工作区菜单，反馈与设置独立可达。首页显示当前阶段、少量进行中任务、一个突出下一动作及原因；空状态可添加机会、编辑资料或记录任职事项。

首次进入可“添加机会”或整理个人资料，任务中再补缺项。资料从明确业务页面进入，文本入口长期可用；文件解析和AI提取按实际接入能力标明，未知不编造。岗位名称自由输入，来源时间系统记录。次要操作放详情或菜单；全局提供“记录反馈”快捷入口。

界面呈现任务、材料和建议，隐藏数据库ID、证据枚举、内部模型名称等用户不需要理解的字段。模拟必须关联目标真实轮次；本期由用户复制Context Pack到新ChatGPT对话进行语音模拟，再上传转写文本。简历保留手动编辑、讨论、版本和本地PDF。

## 简历工作台基线（2026-09-14 用户明确）

简历编辑以用户已有的[妙搭简历工作台](https://fcnxusey6bqe.feishuapp.com/app/app_17dspw78s10)为基础调整。它是可独立使用的模块，后续与职场中台全流程交互。保留其纸面直接编辑、结构化分区和条目、格式、撤销/重做、显式版本、历史恢复与 MD/PDF 导出体验；不能以纯文本编辑框替代后宣称完成。

整个系统负责岗位任务、选材与分析、进度和结果引用；工作台负责简历表达、编辑与排版。用户可从独立入口选择文档，或从机会进入自己的ResumeDocument；每机会最多一份，第一次实际加工才创建，不需要简历可跳过。普通自动保存只更新当前稿，主动保存才产生普通版本；有简历投递时总是自动生成特殊投递版本，即使选用已保存版本。实际投递材料随后不随编辑变化。

原全局editor-main、正式版本、ResumeUse及PDF保留兼容读取和显式复制来源，不推断唯一归属或自动迁移。本期保留纸面编辑体验；参考系统的功能/模板数量不是新增范围，存储适配不构成重做编辑器的理由。

## AI责任

- 理解、提取、选材、匹配、生成草稿、追问、复盘、提出行动和资料修订。
- 显示关键结论来源与未知，不以编造经历填满字段。
- 用户决定重要方向与对外行动。系统记录真实发生的投递/发送，不把草拟等同发生。
- 资料正本和分析分离的全部规则以 [上下文契约](02-context-contract.md) 为准。

## 本地与外部能力

本地应用无需云端发布；PDF、转写和附件写本机。选用远端LLM会发送明确选择的材料，须在界面显示发送范围并提供配置。使用本地LLM可保持分析不出机器，但需测内存、速度与质量。

完全断网可以查看、编辑、导出已存资料并运行已安装模型；不能获得最新招聘或公司信息。电脑睡眠/关机时后台暂停，下次启动恢复。

能力范围与实现状态分别判断：本期目标为Opportunity人工主链及相应任务AI；真实模型质量单独验收。任职卡片及协作保留现状；内置语音、Offer比较等后续能力不列为本周期交付。

不能保证：全网招聘无人值守覆盖、无授权账号读取、领导真实心理、公司未公开内部事实、AI零幻觉、精确录用概率、谈薪结果、从任意PDF无损恢复编辑结构。外部数据不足时输出待验证问题。

## MVP 轻量反馈 Capture（用户确认）

全局一个文本框随时保存，可选上传截图；保存即关闭且保留当前任务。自动记录 created_at、app_version、current_page、相关 entity_id；不采集页面正文、简历、聊天或密钥。反馈存代码目录外本地数据目录，支持查看、追加补充、导出 Markdown/JSON，原话永久保留。反馈默认禁止进入任何职业事实/岗位/简历/面试 Context。当前不做自动分析、代码修改、分类访谈或需求管理；未来分析独立保存。

## 完整产品方案：从职业任务到长期积累

本方案为目标设计，不等于已实现；当前实现和验收只在 execution/STATUS.md。第一性原理：用户需要在信息不全时做更好的决定、完成具体行动，并保留能改变下次决策的证据。信息越多并不天然越好，功能越多也不天然先进。产品价值用「每次准备少重复解释、决策依据可追溯、下一步可执行、经历能再次利用」评估，不承诺前人未做过或成功率。

长期路线连接求职与任职积累，但不是一个必须点完的向导。Opportunity本期主链以上文及模块正本为准；模拟绑定真实轮次，多Offer比较留待后续。任职由用户独立管理，被拒后可复盘或创建新的求职尝试。

| 节点 | 输入 → 用户可使用的输出 | 执行边界/依赖 |
| --- | --- | --- |
| 资料沉淀 | 业务入口Raw或用户手动编辑 → 待确认Patch或直接保存的正式资料 | AI提案确认后立即Apply，用户手改不再二次确认；Context合同区分事实与材料 |
| 创建机会/研究 | 公司、岗位、JD、可选链接及指定来源 → Opportunity与当前岗位情报 | Company主体需明确；Research分公司级/机会级；无网络不声称获得最新信息 |
| 简历与招呼 | 当前事实、JD、相关Research → 独立工作稿及Greeting | 手动路径可用，AI提案不自动变事实，保留纸面编辑和显式版本 |
| 记录已投递 | 用户确认现实已发送，选择当前稿/旧版/无简历 → 唯一Submission | 自动日期、冻结Greeting及实际简历；有简历总生成投递版；phase进入已投递，不要求渠道/备注 |

| Offer / 谈薪 | 实际Offer条款、原材料及沟通 → 当前条件、分析、用户最终决定 | 原件保留；不比较多个Offer、不自动建Employment；结束保留最后phase |
| 任职事务 | 工作卡 + 项目目标、约束、参与者、本人动作、结果证据 → 可跟进事项和阶段记录 | 同时支持多项目、在职求职；结束工作期后仍保留其历史 |
| 领导/同事协作 | 用户导入的聊天、交接、具体事件 → 各方目标、职责/权限、依赖、观察、多个解释及验证动作 | 不做固定人格/心理诊断；反例与环境解释并列；默认仅该工作期可读 |
| 阶段收获 | 已记录的事项与结果 → 有证据的阶段文档、可复用方法、个人资料修改提案 | 原工作记录保留；用户确认之后才更新个人正本，不把总结自证为能力 |

### 降低杂乱经历对分析的影响

不要求用户先整理完人生。入口接受原话，先确定「当前要做的决定」；缺少会改变建议的信息时才追问。Opportunity材料从明确业务入口进入Raw，经对应Skill提出按目标分组的Patch；项目按问题、本人职责、动作、结果、证据组织，区分本人和团队贡献。

每轮先保留职业目标与硬约束，再选择与问题有关的经历及反证，最后按需展开原文。页面提供入选材料及遗漏补充入口；未选中的经历仍保存在本地。技术上以版本依赖和任务范围约束材料，不能只依赖一句“忘记以前的内容”。协议与验收见 02-context-contract.md。

### 领导同事建模的合理形态

采用可更新的协作档案：角色/决策权、共同目标、当前承诺、可观察沟通偏好、关键事件、待验证假设、下一验证动作。一次“迟迟不回复”至少考虑优先级、任务不明确、职责边界、资源限制等解释；根据后续响应更新解释，而非把“对方针对我”固化为事实。建议应回答下一次如何澄清交付和期待、如何给出选项、如何留下结果证据。离开该工作期后，不自动把私人聊天和他人档案送入求职分析。

### 首试范围及反馈迭代

既有首试MVP保留为现状基线，当前改进收敛到Opportunity Vertical。手动闭环与真实AI分别验收；每批沿现有编辑、版本/PDF、事务及Context边界增量实现，不为展示全链路堆空按钮。

每轮改进从实际反馈选出最影响完成任务的问题：主控读原话和可复现路径 → 在反馈外形成改动提案 → 修改所属产品文档 → 一个可验收批次 → 用隔离资料验证 → 回到真实试用。反馈不自动变产品结论，也不由应用擅自修改代码。观察任务完成阻碍、重复输入、资料纠错、建议采用/拒绝理由；不悄悄采集正文或遥测。

## 最新产品定义：职业事实 Wiki（2026-09-14）

个人职业事实仍由Wiki/profile承载，Opportunity与Employment保留各自业务归属。Opportunity目标中Raw是依据，Patch是待确认提案，Wiki与Research/Interview等各自拥有当前认知；不将所有业务数据复制到Wiki。ContextCompiler按任务声明读取当前获准资料。

导航修订为：今天、职业 Wiki、求职机会、简历工作台、任职、面试与复盘、足迹。公司与方向作为可复用业务对象入口，放本地工作区菜单并由机会内引用。页面数量不是对象数量；主要按钮必须带当前对象与用途，不用“记录一下”把所有事件混成一种材料。

| 位置 | 动作 → 落点 / 结果 |
| --- | --- |
| Wiki / 资料入口 | 既有人工原件/候选链保留兼容；本期新业务资料路由及Raw修正遵守Context目标合同 |
| Wiki / 待确认 | 既有候选适配为Patch；用户编辑/接受后立即写目标，拒绝不写事实 |
| Wiki / 当前条目 | 编辑 → 新revision；撤回 → 停止参与分析；查看来源/历史 → 原件/历史只读 |
| 机会 / 顶部 | 公司、岗位、阶段与阶段日期；JD当前内容归Opportunity；周期/方向/组织保留可选兼容 |
| 机会 / 任务AI | 当前任务声明选材 → 预览发送范围 → 运行；旧预览/提案失效则重新核对 |
| 机会 / 岗位情报 | 当前CompanyResearch＋OpportunityResearch；来源明确，公司与团队背景不当本人成果 |
| 简历 / 版本与用途 | 编辑机会自己的稿；普通/投递版本在Resume Workspace回看；旧ResumeUse只保留用途与来源，不当owner |
| 任职 | 项目与Wiki → 当前任职范围；事项、协作、复盘保留原话和独立更正历史；允许选段整理候选，经确认进入Wiki |
