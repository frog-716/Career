# 产品目标与边界

## 核心心智模型

围绕当前职业任务帮助用户理解情况、准备行动、保存结果、积累可复用经验。求职与任职共用资料，但不同工作期和任务的材料按需隔离。价值来自少重复解释、建议有依据、经验可复用，不以功能数量或“全球首次”验收。

## 主路线

个人资料 → 岗位发现与筛选 → 公司研究 → 简历适配 → 招呼与投递 → 沟通跟进 → 模拟/真实面试复盘 → 谈薪与Offer → 任职事项和协作 → 阶段收获 → 更新资料 → 下次求职。

允许多岗位并行、先聊后投、直接约面、反复改简历、多轮面试、拒绝与主动结束、多个Offer比较以及在职求职；不是不可回退的单向向导。

## 用户体验

2026-09-14 最新界面约束：参考 ChatGPT 的白灰极简工作区，左侧导航可完全收起，底部本地工作区菜单承载设置与反馈历史。应用占满一个浏览器视口，标题、模块切换及主动作固定，长列表和正文只在各自面板内滚动，不用整页长卷寻找操作。去掉口号、统计装饰、重复说明；限制只在相关动作处简短说明。

2026-09-15 账户区视觉修订：姓名及 emoji 保持清晰间距和垂直居中，整体右移为头像留空间，窄屏不得通过缩小挤紧姓名解决布局。头像基础边框为正方形；特效参考《斩神》动画的层次与流动感，用户已否定蓝紫霓虹双框、碎线和横穿头像的白色斜线方案。

岗位采用列表与选中岗位详情；详情按岗位、评估、研究、简历、沟通、面试、Offer 切换，当前阶段与下一步始终可达。阶段是计划标记，不自动产生投递事件。任职采用工作卡列表与所选工作详情，事务、协作、收获各自记录和回看。资料、简历工作稿、正式版本及早期文字记录分开；独立简历工作台在当前窗口打开，正式版本可明确关联方向或机会，但关联不等于投递。切换导航或收起侧栏不得丢失已保存内容；长正文按需阅读，不同时展开所有记录。

一级导航：今天、职业 Wiki、求职机会、简历工作台、任职、面试与复盘、足迹。基础资料在职业 Wiki 中管理；公司与方向位于本地工作区菜单，反馈与设置独立可达。首页显示当前阶段、少量进行中任务、一个突出下一动作及原因；空状态可添加机会、编辑资料或记录任职事项。

首次进入可“添加一个岗位”或“导入个人资料”，任务中再补缺项。资料和JD支持自然语言、文件/表格；字段可推断就让AI提取，未知可留空。岗位名称/方向自由输入，来源时间系统记录。次要操作放详情或菜单；全局提供“记录反馈”快捷入口。

界面呈现任务、材料和建议，隐藏数据库ID、证据枚举、内部模型名称等用户不需要理解的字段。语音先能回答再追问，不要求预填改进答案。简历保留手动编辑、讨论、版本和本地PDF。

## 简历工作台基线（2026-09-14 用户明确）

简历编辑以用户已有的[妙搭简历工作台](https://fcnxusey6bqe.feishuapp.com/app/app_17dspw78s10)为基础调整。它是可独立使用的模块，后续与职场中台全流程交互。保留其纸面直接编辑、结构化分区和条目、格式、撤销/重做、显式版本、历史恢复与 MD/PDF 导出体验；不能以纯文本编辑框替代后宣称完成。

整个系统负责岗位任务、选材与分析、进度和结果引用；工作台负责简历表达、编辑与排版。用户可以独立进入工作台，也可以从岗位进入并带回选定版本与 PDF。参考系统的功能数量和模板数量不是本轮新增范围。存储本地化、平台适配和全流程接入不得成为重做编辑器交互的理由。

## AI责任

- 理解、提取、选材、匹配、生成草稿、追问、复盘、提出行动和资料修订。
- 显示关键结论来源与未知，不以编造经历填满字段。
- 用户决定重要方向与对外行动。系统记录真实发生的投递/发送，不把草拟等同发生。
- 资料正本和分析分离的全部规则以 [上下文契约](02-context-contract.md) 为准。

## 本地与外部能力

本地应用无需云端发布；PDF、转写和附件写本机。选用远端LLM会发送明确选择的材料，须在界面显示发送范围并提供配置。使用本地LLM可保持分析不出机器，但需测内存、速度与质量。

完全断网可以查看、编辑、导出已存资料并运行已安装模型；不能获得最新招聘或公司信息。电脑睡眠/关机时后台暂停，下次启动恢复。

可做：资料治理、任务编排、简历编辑/PDF、沟通草稿、转写复盘、按轮语音、Offer比较、任职卡片、协作假设。

不能保证：全网招聘无人值守覆盖、无授权账号读取、领导真实心理、公司未公开内部事实、AI零幻觉、精确录用概率、谈薪结果、从任意PDF无损恢复编辑结构。外部数据不足时输出待验证问题。

## 第一轮控制范围

首轮闭环终点见 [分批路线](07-roadmap.md)。复杂图谱、自动人格评分、自动发送与批量投递、全平台爬虫、云同步、通用Agent平台、微服务不在首轮。岗位源逐个接入；模型与语音能力必须实测，不能以预设分析验收。

## MVP 轻量反馈 Capture（用户确认）

全局一个文本框随时保存，可选上传截图；保存即关闭且保留当前任务。自动记录 created_at、app_version、current_page、相关 entity_id；不采集页面正文、简历、聊天或密钥。反馈存代码目录外本地数据目录，支持查看、追加补充、导出 Markdown/JSON，原话永久保留。反馈默认禁止进入任何职业事实/岗位/简历/面试 Context。当前不做自动分析、代码修改、分类访谈或需求管理；未来分析独立保存。

## 完整产品方案：从职业任务到长期积累

本方案为目标设计，不等于已实现；当前实现和验收只在 execution/STATUS.md。第一性原理：用户需要在信息不全时做更好的决定、完成具体行动，并保留能改变下次决策的证据。信息越多并不天然越好，功能越多也不天然先进。产品价值用「每次准备少重复解释、决策依据可追溯、下一步可执行、经历能再次利用」评估，不承诺前人未做过或成功率。

贯穿路线为：目标与当前资料 → 收集/筛选机会 → 研究公司 → 按岗位选材 → 简历表达与沟通草拟 → 实际行动和跟进 → 面试/复盘 → 谈薪/Offer → 入职工作期 → 事项、协作和阶段收获 → 确认资料更新 → 下一次职业选择。模拟面试可随时插入；谈薪偏好在早期记录，具体比较在条款出现后进行；被拒后可复盘、结束或另寻机会。没有必须一路点完的向导。

| 节点 | 输入 → 用户可使用的输出 | 执行边界/依赖 |

| 资料沉淀 | 自述、经历、项目证据、技能与目标 → 当前条目、来源、未知和冲突；AI修改差异 | 手动编辑随时可用；明确唯一的用户修改指令可落库回显，AI推断必须确认 |
| 搜岗/筛选 | 搜索条件或手动JD/表格 → 去重机会列表、硬门槛、支持证据、缺口、继续/待补信息/排除理由 | 接入已获授权且可用的来源；手动入口长期保留；不给虚假的精确录用概率 |
| 公司研究 | 明确公司主体/岗位 + 官方站点、产品、公告等来源 → 业务、岗位目标、风险、反证、待问问题 | 外部搜索需要网络与来源Adapter；保存来源URL、采集日期、引文位置；重名公司先消歧 |
| 简历工作台 | 所选当前经历 + 当前JD + 本轮表达方向 → 结构化编辑提案 → 人工采用 → 独立正式版本/PDF | 沿用既有纸面编辑器；逐条before/after、保留手改；旧稿不能自动充当事实 |

| 领导/同事协作 | 用户导入的聊天、交接、具体事件 → 各方目标、职责/权限、依赖、观察、多个解释及验证动作 | 不做固定人格/心理诊断；反例与环境解释并列；默认仅该工作期可读 |

### 降低杂乱经历对分析的影响

不要求用户先整理完人生。入口接受原话，先确定「当前要做的决定」；缺少会改变建议的信息时才追问。原材料进入收件箱，整理为可单独修订的条目；项目按问题、本人职责、动作、结果、证据组织，区分本人和团队贡献。

每轮先保留职业目标与硬约束，再选择与问题有关的经历及反证，最后按需展开原文。页面提供入选材料及遗漏补充入口；未选中的经历仍保存在本地。技术上以版本依赖和任务范围约束材料，不能只依赖一句“忘记以前的内容”。协议与验收见 02-context-contract.md。

### 领导同事建模的合理形态

采用可更新的协作档案：角色/决策权、共同目标、当前承诺、可观察沟通偏好、关键事件、待验证假设、下一验证动作。一次“迟迟不回复”至少考虑优先级、任务不明确、职责边界、资源限制等解释；根据后续响应更新解释，而非把“对方针对我”固化为事实。建议应回答下一次如何澄清交付和期待、如何给出选项、如何留下结果证据。离开该工作期后，不自动把私人聊天和他人档案送入求职分析。

### 首试范围及反馈迭代

优先交付可持续记录的本地MVP：当前资料、手动岗位、阶段/下一步/日期、研究/沟通/面试/Offer文字记录、原版独立简历与PDF、工作卡与阶段收获、全局反馈。真实AI分析依赖Provider接通；选材和结构化简历AI接入按路线补齐。手动记录不冒充研究或面试AI完成，不为展示全链路堆空按钮。

每轮改进从实际反馈选出最影响完成任务的问题：主控读原话和可复现路径 → 在反馈外形成改动提案 → 修改所属产品文档 → 一个可验收批次 → 用隔离资料验证 → 回到真实试用。反馈不自动变产品结论，也不由应用擅自修改代码。观察任务完成阻碍、重复输入、资料纠错、建议采用/拒绝理由；不悄悄采集正文或遥测。

## 最新产品定义：职业事实 Wiki（2026-09-14）

以职业事实 Wiki 为资料核心，Opportunity（求职机会）与 Employment（任职）为两条业务主干；Context Compiler 每次按任务读取获准的最新版。Raw记录发生过什么，Staging存尚未确认的解释，Wiki存目前采用的认知，AI产出建议；四者不能相互冒充。

导航修订为：今天、职业 Wiki、求职机会、简历工作台、任职、面试与复盘、足迹。公司与方向作为可复用业务对象入口，放本地工作区菜单并由机会内引用。页面数量不是对象数量；主要按钮必须带当前对象与用途，不用“记录一下”把所有事件混成一种材料。

| 位置 | 动作 → 落点 / 结果 |
| --- | --- |
| Wiki / 原始资料 | 添加原文或来源说明 → 只读原件；整理 → 待确认候选 |
| Wiki / 待确认 | 修正 → 候选revision；确认 → 同范围当前条目；拒绝 → 保留原件、不写事实 |
| Wiki / 当前条目 | 编辑 → 新revision；撤回 → 停止参与分析；查看来源/历史 → 原件/历史只读 |
| 机会 / 岗位 | 编辑招聘信息；编辑关联 → 周期、方向、公司、团队；未知允许留空 |
| 机会 / 评估 | 勾选Wiki → 预览完整本轮包 → 明确发送；旧预览失效则重建 |
| 机会 / 研究 | 记录研究原话；相关Wiki → 本机会范围；公司与团队背景不当本人成果 |
| 简历 / 版本与用途 | 编辑当前工作稿；选正式版本 → 方向通用/机会定制用途；固定PDF，关联不等于投递 |
| 任职 | 项目与Wiki → 当前任职范围；事项、协作、复盘保留原话和独立更正历史；允许选段整理候选，经确认进入Wiki |
| 反馈 | 记录问题 → 独立反馈空间；不自动变事实或修改代码 |

本轮可用的是人工资料治理与显式引用；不把“整理”命名为AI自动提取。目录/Git地址仅登记，不声称已经读取代码。Project项目可以独立于任职存在，并引用多种来源；任职私聊默认不能被普通求职分析选中。需要公开复用某项成果时，另行整理允许使用的个人证据并确认，不复制私聊到求职包。

完整对象职责、字段、可变/不可变规则及当前/未来区分仅维护于 03-architecture.md 最新领域模型；产品不另建第二份字段规格。


## 冷启动整改后的事实生命周期（2026-09-15）

基础资料只拥有姓名、邮箱、电话、微信、GitHub及个人网页；长期经历、能力、职业目标及地点/出差等限制属于个人 Wiki。TargetRole 是可复用的岗位类型目录，SearchCycle 是某次求职计划；两者帮助归类机会，不充当个人约束正本。具体招聘条件属于机会的 JD。

## 可操作全链路案例（2026-09-15 用户明确）

首个可正式使用版本完成前，当前本地工作区保留一套可实际编辑、推进和回看的虚构案例。案例覆盖两条主干及跨模块引用：机会、研究、选材分析、结构化简历固定版本/PDF、投递、沟通、面试、Offer，以及任职、项目、参与者、工作事件、成果、证据和 Wiki 回流。

案例对象统一显示“案例”并记录固定 dataset id；重复装载不得生成重复记录。案例不得覆盖用户唯一基础资料、现有机会、简历或附件。设置页提供由用户主动触发的装载与删除；删除只清理该 dataset id 明确拥有的对象与附件，默认不自动清理。真实资料和案例可同时存在，用户在熟悉系统并确认第一版可正式使用后自行删除案例。
