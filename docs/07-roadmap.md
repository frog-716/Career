# 分批落地路线

当前实施、证据与外部 Gate 见 [STATUS](execution/STATUS.md)。本页描述目标批次和推进门槛，不承担当前状态正本；已完成批次的细节保留在对应 execution 文档。

| 批次 | 用户可见结果 | 完成条件 |
| --- | --- | --- |
| B00 项目启动 | 可启动的本地任务首页、空状态、数据目录和诊断 | HTTP打开；参考资产与新应用分开；说明真实能力状态 |
| B01 当前资料 | 人工编辑/导入、来源、修订、任务资料包、提案确认、模型配置入口 | C01–C08核心机制、持久化；真实模型与测试模式区分 |
| B02 岗位与研究 | 手动JD/表格、可删除列表、评估、公司来源研究 | 岗位引用不串；缺项/失败诚实；公司主体明确 |
| B03 简历与投递 | 可手改本地工作台、AI差异、版本/PDF、招呼、投递与聊天 | D01–D03、D05；实际PDF可回读；实际事件显式登记 |
| B04 面试与决策 | 转写复盘、对话模拟、练习、薪酬/Offer比较 | J01文本闭环，D04、J03/J04；真实AI分析验证 |
| B05 任职闭环 | 工作卡、事项、协作解释、行动结果、阶段总结、资料更新 | J02；推断不写事实；工作/求职材料隔离 |
| B06 操作便利 | 按轮语音、一个实际可接的岗位自动搜索来源 | J05/J06实际验证；无法访问的来源明确降级手动入口 |

所有批次包含相关可靠性回归，B06结束做R01–R05与完整隔离案例验收。无Gate时按顺序持续推进；可以并行独立实现，但核心资料契约先固定。缺外部能力时完成其他闭环，准确列出未完成项，不把降级当完整能力。

2026-09-14 的首次试用目标——任务首页、手动机会/下一步、独立简历/PDF、任职记录和全局反馈——已经完成，历史证据见 [任务工作台首试](execution/TASK-WORKSPACE.md)。真实 AI、语音和自动搜岗仍须按各自能力实测，不造个人资料或请求凭据进聊天。

当前优先顺序以本页末尾“最新模型后的优先顺序”和 STATUS 为准：先完成真实 Provider 与结构化内容闭环，再推进团队级研究、文本面试复盘及其他外部能力。每段均先预览实际材料再运行并分别验收；具体排期取决于可访问数据源、模型配置和用户反馈。

推进门槛：新输入能正确留存 → 当前任务可完成 → 当前依据可检查 → 结果可采用/拒绝 → 重启和反馈不丢。每达到一个门槛就可使用；阻塞外部能力时持续完成独立部分。第一轮完整AI闭环仍要求真实分析、真实结构化简历适配、本地PDF与实际投递记录关联，不以手动记录版代替该验收。

后续候选只在使用证据支持时推进：更多平台、连续双向语音、语义检索、知识网络、数据分析高级能力、外部项目深度集成。

## 任务文件模板

```text
ID / 状态 / 依赖
本批用户结果
输入和Interface契约
允许修改路径与文件所有权
对应验收ID及实际验证方式
实现范围、验收条件和停止条件
完成证据与审查结论
剩余限制
```

任务初稿由主控根据实际工具链编写，不将本表机械转换成大量空票。先把当前批次做具体。

## 最新模型后的优先顺序

本轮 [Wiki与业务对象](execution/WIKI-DOMAIN.md) 建立原件→人工候选→确认Wiki→显式选材→实际请求；加入公司/组织树、周期/方向与机会引用、简历版本用途。旧手动机会和任职ID保留，不迁空库。

固定版本/PDF投递及人工事实→简历→投递→记录→候选→确认链已于冷启动整改落地，见当前STATUS。下一完整纵向任务优先：真实Provider配置与AI提取/冲突候选（先保持人工可用）→ 多ResumeDocument与 role/opportunity scope、结构化内容patch与原版排版隔离 → 团队级带来源研究、文本面试复盘。其后 Repository Ingestion、阶段/人物参与关系、EvidenceLink页行定位、音频/自动搜岗。所有对象完整图不等于本轮承诺全实现；每项必须达到输入留存、来源正确、确认可撤回、跨任务隔离、实际使用可验收再扩展。
