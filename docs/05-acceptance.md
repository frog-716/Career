# 验收契约

真实运行才记录通过；本文件是未来应用的验收需求，不是已有测试报告。工程先用 [虚构案例](../fixtures/scenarios.json)。测试关注Interface、主路径、持久化、关键回归；不为未实现未来需求堆测试。

## 上下文（关键批次必测）

- C01 当前经历从旧说法更正：后续实际模型请求仅含当前事实；历史事件复盘须显式标用途。
- C02 模型运行中更新资料：旧结果stale，不直接应用；新请求读新revision。
- C03 旧助手消息、缓存、失效摘要不带回已更正事实；删除条目不被索引复活。
- C04 新分析不自动把前次分析当事实；缺证据不生成量化结论。
- C05 人工与AI并发修改产生冲突提示；同提案重复应用只生效一次。
- C06 恶意JD/转写无法触发任意文件、SQL、出网或事实写入工具；输出解释仍人工核对。
- C07 相关性筛选保留硬约束、关键反证；用户可补充被漏掉的经历。
- C08 修改已核验事实内容使核验失效；用户确认不自动等于材料验证。

## 资料与事件

- D01 自动保存只更新工作稿；正式保存产生不可变版本；导入/恢复不污染正式版本历史。
- D02 同工作稿lineage的经历ID保留；新文件导入不自动关联旧事实。
- D03 保存版本不创建投递；记录投递引用正确版本，修改当前稿不改变历史PDF。
- D04 原始转写不覆盖，纠正有来源；后续改进答案不能冒充实际回答。
- D05 删除岗位后不再出现于活动列表或下轮采集；历史投递/面试仍可回看。

## 实际任务闭环

- J01 添加真实结构的虚构岗位→有来源分析→简历与PDF→明确记录投递→聊天跟进→面试复盘→练习→Offer与下一动作。
- J02 一张工作卡→交接/聊天→多个可证伪解释→行动→结果→阶段总结→确认新经历。
- J03 多岗位不串材料；多轮面试与先聊后投可用，不强制单向步骤。
- J04 模拟必须先回答再追问；真实高频与练习次数分开；模糊转写不作确定评分。
- J05 首个招聘源读到真实数据或明确报不可访问；采集失败不等同零岗位。
- J06 按轮语音实际录入、转写、追问、播放；文字降级可用。无实测不报“自然语音已完成”。

## 可靠性

- R01 关闭重启后工作稿、正式版本、投递、面试、工作事项及PDF可回读。
- R02 保存中断、重复请求、附件失败不造成假成功/重复事件。
- R03 备份后在隔离目录恢复，数据库与引用附件均正确；升级失败可回退匹配版本。
- R04 数据与静态目录分离，密钥不在浏览器/Git/日志；远端请求只有允许的资料。
- R05 初次打开有明确开始动作；离开后可继续任务，常用操作不需要手填内部ID。

## 模型验收

Spy/Fake Provider只验证请求与工作流；界面和报告必须标“测试模式”。配置真实供应方后至少运行J01中的JD分析和面试复盘；检查引用、编造、遗漏及建议是否有用。不能用模型自评分或预设示例替代。

缺模型凭据时完成可独立验收部分，状态记“运行时AI未验收”，说明需在设置页补的具体配置；不修改供应方为未经用户选择的服务。
