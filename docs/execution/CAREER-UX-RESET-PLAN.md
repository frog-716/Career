### 主 Agent 已核对的实现缺口

1. `frontend/src/wiki-semantic-bindings.ts`：D4 建立 `[data-d4-flow]`，成功后复用的 `renderCompilerPatch` 只寻找 `[data-d2-flow]`，找不到便返回。当前代码存在“结果已经保存、弹窗仍没有建议”的确定显示断点。本轮只记录，不打补丁。
2. D4 confirm 后只禁用按钮并 await execute，没有明确进入处理中视图，也没有此流程的状态轮询。
3. `semanticWikiUI.scope/selected` 是内存变量；默认 all。`main.ts` 仅在 cognition scope 读取 Cognition workspace，刷新不能依靠 `#wiki` 恢复这个子位置及其待处理建议。
4. 后端已有持久化 `ai_operations`、dispatch slot、结果引用和 Proposal，应用启动会对中断操作做恢复。应补全这些既有事实的用户可见投影，不另建一套任务事实库。
5. Wiki 用知识类型做列表标题，正文放 small；对象页遍布类型/当前/标签/来源及操作，任职内展开人物又嵌入一套卡片。呈现单位与用户关心的“哪件事、现在如何”不一致。

### 跨页面合同复核（隔离数据，非正式库）

- **资料归属冲突已复核**：同一项目原文出现在任职和人物 workspace 返回中，三处原文的 `scope_type` 都是 project。`sources.list_sources` 使用“允许引用”的关联范围判断来构造“本对象资料”列表；D3文案却承诺只显示自己的原文。这是“可以引用”与“直接属于”的混用。不能仅把小字删掉掩盖。UX-1需先明确工作区直接资料边界；关联来源仅在明确的来源选择/追溯中按现有引用合同出现，不能自动成为人物自己的资料。本轮无证据表明发生真实外发泄漏，不作这种推断。

### 主 Agent 不采纳或调整的建议

1. **不采纳“没有P0”结论。** 独立测试的项目建议能恢复，但用户真实D4建议不可见且长时间不知状态；代码也有明确显示断点。两条流程不能互相代替，因此统一AI状态为P0。
2. **不采用仅把按钮改成“正在整理…”的最小补丁。** 仍需持久操作入口、刷新恢复、结果找回和安全状态读取；否则根本心智问题未解决。
3. **不把关联资料改名后继续放在人物自己的资料区。** 已确认D3规则要求直接对象资料，引用许可不能替代归属。明确相关资料的需求将来可单独设计，不在这里扩大读取。
4. **不采用Wiki首页直接“添加第一份资料”的万能入口。** 首页引导创建/选择项目或任职，再从确定对象添加，保留已确认的明确业务入口边界。
5. **不在草稿、版本、投递按钮旁继续增加一圈解释。** 先整理动作层级、修复已保存回显；仅保留影响用户决定的短提示。
6. **不因Fresh-Eyes觉得长期认知解释清楚而恢复教学段落。** 用户已有明确减法要求；保留标题、实际经历、来源及条件，把概念说明移出日常流程。

## 2. 重构原则

每页只回答一个首要问题。内容先于分类，业务对象先于数据库类型，操作结果可以离开页面后找回。

优先顺序：**删除重复内容 → 合并相同动作 → 隐藏低频信息 → 改文案 → 调整层级 → 必要时才新增能力**。

不能用更多解释弥补结构错误。保留来源、历史、确认、并发和隐私边界，但让它们在用户需要判断时出现。

## 3. 新导航与过渡

```text
Career                         [AI 处理中 1 / 待处理 1] 仅有任务时出现

Wiki
机会
项目
任职

设置 / 反馈                    低优先级工具区
```

- Wiki = Career 记住的重要信息；机会 = 求职推进；项目 = 长期在做的事；任职 = 工作环境及其中的人。
- Person 从所属任职或项目中的人物进入，保持对象 ID；不新增全局人物一级页。
- 长期认知属于 Wiki 的可见入口，不藏在一个混合范围下拉框中，也不新增第五个一级导航。
- AI 状态入口是可恢复的操作入口，不是新业务模块或全局资料 Inbox。跨对象只显示任务类型、数量和状态；对象名称/建议正文在所属页面打开后读取，不把机会私有知识带入全局 Wiki。
- 过渡期保留现有“简历工作台”可访问性，先补足机会内“编辑简历”和返回所属机会的路径。对应 Resume Phase 完成路径等价验收后，再移除一级入口。旧版求职资料改为明确的历史入口，不承接新增长期资料；仍有效的基础资料提供设置内直接入口。旧链接跳到同一份文档；不复制或自动重绑旧稿，不动 Submission 冻结材料。
- 当前用户保存的导航顺序不静默丢失；迁移时保留四个有效入口的相对顺序，失效 Resume 入口退出一级菜单但保留深链接恢复策略。

## 4. Wiki 首页：Career 记住了什么

唯一首要任务：**找回一条现在值得参考的信息，并知道它来自哪里**。

```text
Wiki                                              [AI 待处理 1]
Career 记住的重要信息

[项目]   [任职]   [人物]   [长期认知]

最近更新
项目名称 A  →  原型改为周一交付                    今天
任职名称 B  →  本月先完成内部评审                  昨天
[查看更多]

项目中的信息
项目 A        一句已有知识正文                    [打开]
项目 B        一句已有知识正文                    [打开]
```

- 默认按对象组织近期当前知识；标题用正文可辨识内容，类型退为次级标识。不是默认展示全库行和筛选器。
- 最近更新是既有 revision 的只读投影：记录“哪条内容发生变化”，不建新的活动/历史系统，不把被撤回的旧正文伪装成当前。
- 项目/任职/人物/长期认知是本页的查看方式。切换到某对象时保留可链接的对象位置，打开同一知识 ID。
- “个人职业资料”现有有效知识仍保留一个次级入口；不能在四分组设计中默默丢失。机会私有知识继续只在对应机会内可见。
- 默认只看当前；“不再有效的信息”放更多菜单，历史在条目详情。Tags 按需筛选，不常驻两个下拉框占首屏。
- 全局首页不提供无目标的“添加资料 / 写入 Wiki”双主按钮。进对象后添加；手工记一条保留为对象内次级动作，明确用户来源，允许没有原文。
- 当前知识全文、来源标题与记录时间可在详情阅读。摘要只是列表截取，不构建第二份正文或AI摘要库。

## 5. Project：现在在做什么

唯一首要任务：**接上这个项目当前的工作**。左侧只负责切换项目；右侧负责当前项目。

```text
项目列表                星舟原型                  进行中  [更多]
[新建项目]              一句项目描述
星舟原型                #AI  #个人项目    任职：无
北岸工具
                        [概览] [资料] [协作人物]
                        当前要点
                        原型改为周一交付             [来源]
                        先完成内部评审               [来源]

                        最近变化
                        今天 · 更新了交付计划
                        昨天 · 添加评审记录

                        最近资料                 [添加资料]
                        评审记录                     [打开]
                        [全部资料]
```

- 项目名、四状态、描述、可选任职明确；Tags 是轻量标签，无“无 Tags”占位。编辑统一进一个入口。
- 当前要点引用现有 Wiki，不重新保存概述。首版可按最近更新展示少量，并明确“最近更新”；不能冒称算法知道最重要。若要用户置顶现有条目，作为独立可选展示偏好设计，不扩成任务/优先级实体。
- 没有知识就简短提示“还没有整理过项目资料”，只给添加资料动作。已有资料无知识时，提供打开该资料整理；不自动调用。
- 协作人物作为正式页签，与旧记录无关。任职项目内只列合法人物；一行姓名、任职角色、项目角色并明确两个字段含义。个人项目不强制显示空协作者表单。
- 旧 Event/Achievement/Evidence 的读取移至更多 → 旧工作记录，默认不占核心区；D/E 退役前继续可访问，不删除数据、不扩建旧编辑器。

## 9. 统一 AI 交互与恢复合同（P0）

```text
AI 会看什么 → 开始 → 正在处理 → 发现 N 条建议 → 逐条处理 → 完成
                          ├─ 没有需要更新的内容 → 完成
                          ├─ 失败
                          └─ 暂时无法确认结果
```

### 用户可见状态

| 状态 | 页面显示与动作 | 持久化与安全约束 |
| --- | --- | --- |
| 准备 | 正在准备本次资料；可关闭 | prepare不发送。未准备完成不能开始 |
| 确认 | 实际材料全文、所属对象；开始/取消 | 与实际 DTO 一致，技术详情折叠；stale须重新确认 |
| 处理中 | 正在整理；已用时；可以离开，稍后查看 | 单次确认、同一幂等意图；关弹窗不代表取消；有持久化操作ID |
| 建议待处理 | 发现N条建议；继续处理 | 复用Proposal；pending不写知识；全局只报数量和安全任务 metadata |
| 完成 | 已更新X条，未采用Y条；返回所属对象 | 逐条结果可追溯；0条显示“本次没有需要更新的内容” |
| 失败 | 本次没有更新内容；关闭/查看详情 | 分开用户输入、发送前失败、结果不可安全使用；不责怪用户、不自动重试 |
| 结果未知 | 暂时无法确认结果，未更新内容；查看状态 | 不冒称失败/成功；不再发一次；只查询原操作 |

- 点击开始后立即切换处理中，按钮不能留在可重复发送的状态。使用明确阶段/已用时，不虚构百分比，不无限 spinner。
- 首选复用现有 ai_operations / result_ref / Proposal。确认接口需要尽快返回操作引用，后台工作继续；关闭、导航、断网、刷新后的状态都来自服务端。是否调整为202/后台执行应先写接口测试，再实施，不能只在前端造一个假任务。
- 建议提供受限的操作摘要读取：操作ID、任务类型、状态、开始时间、结果引用、待审数量、安全错误码。查状态绝不 dispatch；不通过 `/api/state` 大包获取 Profile/Resume/Person 内容。
- URL保存当前对象、页签与正在查看的操作/建议引用；浏览器本地存储只作导航提示，不成为任务真相。
- 处理中有界退避轮询；页面隐藏降低频率，恢复焦点立即核对。同一时刻只有一个查询循环；达到客户端等待阈值只改成“仍在等待/查看状态”，不能推定 Provider 失败或新建请求。服务端超时/进程中断沿用既有 outcome_unknown 规则。
- 用户回到任一主页面能看见“1 个 AI 结果待处理”；点击进入既有操作的所属上下文。用户离开后无需记住发起入口。
- 对同一输入已有运行中/待审建议时引导打开既有操作，避免用户不知情地生成另一套建议；明确新任务仍重新预览确认，不删除旧审计。

## 10. 空状态、文字与视觉规则

### 空状态

- 全新 Wiki：“还没有整理过的信息。”主动作进入创建/选择一个项目；不展示一排禁用的写入按钮。
- 对象无资料：“添加一份资料，之后可整理成重要信息。”一个添加动作，不自动发模型。
- 有资料无知识：“这份资料还没整理。”进入对应资料；可以手工记一条。
- 无人物/无关联项目：简短一行和按需入口；个人项目不因无任职出现警告。
- 无长期认知：提供选择经历入口；经历不足时显示缺少什么，不制造无意义空卡片。
- 加载与空数据分开：读取失败显示“暂时没能读取”并允许重新读取；不可显示成“没有资料”。

### 文案

| 当前词或句式 | 目标 |
| --- | --- |
| Raw | 资料 / 原文 |
| Fact / Observation / Hypothesis | 已确认事实 / 观察 / 待验证判断；内容优先、类型次级 |
| scope / 当前范围 / 对象 | 具体项目、公司或人物名称 |
| Provider | 普通操作写AI；模型名称只在发送详情/设置 |
| revision / source_ref / confirmed | 历史 / 来源 / 正常UI不显示确认技术状态 |
| 当前理解 | 对象页“重要信息”或“当前要点”，不要求先学懂Wiki |
| 无 Tags / 没有伪造原文来源 / 资料不会复制 | 无值不占位；手工来源简写“你记录的” |
| 输入格式不正确，请检查后重试 | 按实际失败责任说明，模型失败不要求用户修输入 |

删除重复原则说明和教学段落；必须保留会影响当前决策的信息：保存目标、发送范围、正在处理、未写入、当前/历史差异、来源不可用、并发冲突。

### 视觉

- 沿用熟悉的字体家族，不擅自替换字体。建立少量字号层级：建议正文16、次要文字14、页标题26–28、段标题18–20；13以下不承载正文或必要操作。具体值在一页低保真实现验收后统一，不能全局覆盖 Resume 编辑器字号。
- 首屏只一个实心主动作；其他动作文本化或收更多菜单。编辑/历史/退役不在每条信息里排成一排按钮。
- 正文先出现，类型与时间退后；不在列表与详情重复全文、对象名和类型标题。
- 一页一主滚动区；来源/预览长正文可局部滚动，避免三层嵌套滚动。列表栏负责定位，正文栏负责阅读。
- 内容列保持可读宽度（建议正文约65–80个拉丁字符等效宽度）；宽屏扩间距，不把每句拉满屏。窄屏列表/详情分步呈现。
- 以留白、段标题、细分隔组织；不让每一段都包卡片。对齐统一到一条文字起线，按钮不随段落长度上下漂移。
- 键盘焦点、错误提示、保存反馈可感知；颜色不单独承担状态含义；200%缩放与常用窗口尺寸无关键动作丢失。

### 各批回归风险与验收

- **AI**：点击一次最多一次dispatch；pending不写Wiki；关闭/刷新/断网/重启均可核对既有任务；查状态不发Provider；无结果不等于失败；不知道结果时禁止重试捷径。
- **导航**：刷新/后退恢复对象、子页及选中条目；旧深链接可达；不因路由变动复制Project/Person或Resume。
- **隐私**：全局摘要不能读Profile/Resume/Person正文；机会知识不混进Wiki首页；Preview逐字段等于DTO，Cognition不读Raw正文。
- **写入**：手工CRUD成功立即刷新当前区域；CAS失败保留输入；edit_accept保存用户版本；任职role与project_role互不修改。
- **历史**：只有当前revision显示当前；retired默认隐藏、历史可达；Raw hash完全不变；来源版本变化不展示新正文冒充旧来源。
- **视觉/无障碍**：内容不再靠小字承载；键盘可完成主路径；窗口缩放不丢保存/返回按钮；不动简历正文排版。
- **规模**：空库、多个任职/项目、长资料、长知识列表均测试；采用有界列表与现有分页，不截断实际发送全文。
- **所有权**：实施前重建文件/hunk保护清单；13个Resume文件、AGENTS未知hunk、Agent/Skill文件隔离；README独立hunk；不以clean working tree为目标。
- **最终验收**：先自动验证，再独立盲审，最后用户一次一个短场景；任何一层未完成明确记录，不以截图漂亮替代业务闭环。

### backend → 用户状态

| 后端事实 | 用户状态 | 恢复方式 |
| --- | --- | --- |
| prepare进行中 / 已prepared、尚未确认 | 准备中 | 当前Preview；不会作为已发送任务创建另一条记录 |
| 用户已确认，reserved / confirmed / dispatching | 处理中 | 查询原operation；关闭/切页/刷新不取消，不重发 |
| Provider返回成功但本地校验/持久化未完成 | 处理中 | 后端未提交succeeded前不冒充完成 |
| succeeded + pending Proposal（含部分已审） | 待处理 | 原Proposal ID，重新读取每条审批状态；显示已处理N/M |
| succeeded + resolved/accepted/rejected Proposal | 完成 | 沿既有Proposal终态；不再累计待处理 |
| succeeded + 合法0 Patch | 完成 | 短暂完成提示，无永久待办 |
| failed + invalid_result/结果不可安全使用 | 失败 | 没有修改资料，无默认重试 |
| failed + prepared_request_expired（含旧 Missing 过期记录且未 dispatch） | 准备中 | 预览已过期、尚未发送；必须用户重新预览，不自动重新准备 |
| failed + prepared_request_stale | 准备中 | 说明预览后资料变化；手动重新确认，恢复本身不prepare |
| outcome_unknown（含进程中断后保守恢复） | 结果未知 | 查询原operation；无自动/一键重试 |
| Proposal superseded | 完成 | 按真实终态提示已被替代，不伪装用户拒绝 |
| Proposal invalid/failed | 失败 | 不开放审批，不写Cognition |
| 读取状态网络失败 | 暂时无法读取状态 | 保留原operation，不推断Provider失败，不发送 |

`ai_preparation` 是既有发送前快照，不是另建的UI任务。每个实际operation状态通过固定优先级投影为六种用户状态之一；无匹配状态保守显示结果未知。任务映射覆盖Wiki Compiler、Cognition、Research搜索/整理、Resume优化、面试及旧机会分析；完整Proposal恢复本批限Wiki/Cognition，其余模块只投影真实状态并前往所属页面。

### 接口、执行和UI边界

- 新增只读 `GET /api/ai/activity` 与 `GET /api/ai/activity/{operation_id}`；仅返回任务名、最小对象身份、六状态、时间、原Proposal引用与审批数量。不输出Raw/Wiki/Resume/Profile正文、manifest、模型结果、错误正文或Secret。
- 正本继续为ai_operations与原Proposal。无新表/迁移、通知记录、前端任务持久化或后台队列。现有同步HTTP handler在服务端线程执行，页面关闭不会取消它；隔离线程与浏览器断开验证持续执行。进程退出仍按现有recover机制终结未知状态，不承诺进程重启后继续计算。
