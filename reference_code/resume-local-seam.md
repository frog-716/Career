# 简历工作台本地化接缝

旧项目本地代码曾在浏览器生成PDF，然后调用平台接口保存版本和对象存储。可复用的是“结构化工作稿、编辑和渲染分离、版本保存显式发生”的思路；不需要继续依赖云端。

## 新项目的交接

```text
JD + 当前资料 → Analysis生成差异 → 用户讨论/确认
                                    ↓
                               ResumeDocument
                                    ↓ 显式保存
                    ResumeVersion + documentSnapshot + PDF文件
                                    ↓ 实际投递
                                Application
```

建议编辑器向Resume模块交付结构化文档和模板标识；Resume模块冻结版本，Artifacts保存PDF及哈希。保存版本与PDF导出可分阶段，但必须显示缺PDF/失败状态，不能虚报完整归档。

保留结构化源与原PDF。旧代码曾使用截图嵌入PDF，可能缺少可选中文文本；新项目可改本地打印渲染，但须验证字体、A4分页、文本提取和历史PDF不变。不能把PDF可打开等同于完整编辑结构可恢复。

跨导入文件的经历自动识别、候选人事实数据库和自动事实核验不属于编辑器职责。编辑自动保存只改工作稿；导入前/恢复前备份是RecoveryPoint。

## 妙搭既有资料的迁出（有需要再做）

用户明确选择导入后，只读取其可访问的结构化当前稿、历史版本与PDF，保留原版本ID映射和来源时间。先验证本地可打开与编辑，再决定是否停用云端。未取得文件本体的历史链接不计为成功迁出。新项目起步不要求妙搭登录，也不猜测线上部署与旧本地代码完全一致。
